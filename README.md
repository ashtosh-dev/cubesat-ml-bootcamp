# CubeSat ML/CV Bootcamp

Beginner-friendly hands-on project: train image-classification models on
a laptop, evaluate them, optimize them, and deploy inference to a
Raspberry Pi 5. CIFAR-10 is used for guided notebooks; EuroSAT is the
adaptation challenge.

## Learning outcomes

-   Inspect image datasets and prepare reproducible splits.
-   Train a CNN from scratch and fine-tune MobileNetV2.
-   Evaluate models, inspect errors, and compare results.
-   Convert a model for edge inference and test it on Raspberry Pi.
-   Adapt the workflow to satellite land-cover classification.

## Requirements

**Training laptop:** Ubuntu/WSL2, Python 3.12, 8 GB RAM minimum (16 GB
recommended), internet access. NVIDIA GPU is recommended but optional;
CPU training is possible but slower.

**Edge device:** Raspberry Pi 5 with 64-bit Raspberry Pi OS. A supported
camera is optional for live-camera inference. ESP32 is better suited to
sensors/telemetry than these image-classification models.

## Laptop setup (Ubuntu/WSL)

Open the project directory:

``` bash
cd ~/projects/cubesat-ml-bootcamp
```

If you have not cloned the repository yet, replace the placeholder:

``` bash
git clone https://github.com/ashtosh-dev/cubesat-ml-bootcamp.git
cd cubesat-ml-bootcamp
```

Create and activate the environment:

``` bash
conda create -n cubesat-ml python=3.12 -y
conda activate cubesat-ml
```

Install dependencies and check them:

``` bash
python -m pip install --upgrade pip
python -m pip install -r requirements-train.txt
python -m pip check
```

If `pip check` reports conflicts, stop and share the complete output
with the team lead rather than installing random versions.

Register the notebook kernel and launch Jupyter:

``` bash
python -m ipykernel install --user --name cubesat-ml --display-name "Python (cubesat-ml)"
jupyter lab
```

In Jupyter, select the **Python (cubesat-ml)** kernel.

## Verify the environment

Run `notebooks/00_system_check.ipynb`. You can also run:

``` bash
python - <<'PY'
import sys
import tensorflow as tf
print("Python:", sys.version)
print("TensorFlow:", tf.__version__)
print("GPUs:", tf.config.list_physical_devices("GPU"))
PY
```

An empty GPU list means TensorFlow is using CPU; the notebooks can still
run, though more slowly.

### EuroSAT challenge

Load and inspect EuroSAT, identify its labels and image dimensions,
adapt preprocessing, create train/validation/test splits, train or
fine-tune a model, evaluate it, and explain how the pipeline differs
from CIFAR-10. Do not assume CIFAR-10 labels or preprocessing apply.

## Raspberry Pi deployment

Train on the laptop; use the Pi for inference.

On the Pi:

``` bash
sudo apt update
sudo apt install -y python3-venv python3-pip
python3 -m venv ~/cubesat-ml-venv
source ~/cubesat-ml-venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-pi.txt
```

Copy the converted model from the laptop (replace placeholders and
filename):

``` bash
scp models/cifar10_model.tflite <PI_USERNAME>@<PI_IP_ADDRESS>:/home/<PI_USERNAME>/
```

On the Pi, follow the inference notebook/script instructions. Confirm
that preprocessing matches training, labels are mapped correctly, and
inference time is recorded. For camera inference, test the camera
independently first.

## Suggested five-person team roles

1.  Data: dataset inspection, preprocessing, split documentation.
2.  CNN: baseline training and experiment tracking.
3.  Transfer learning: MobileNetV2 training and comparison.

## Team workflow (three students + one mentor)

The team has **three student members and one mentor (you)**. Suggested
responsibilities:

1.  **Student 1 --- Data and preprocessing:** dataset inspection,
    preprocessing, train/validation/test splits, and dataset
    documentation.
2.  **Student 2 --- Model training:** baseline CNN and MobileNetV2
    training, experiment tracking, and model checkpoints.
3.  **Student 3 --- Evaluation and edge deployment:** evaluation

4.  **Mentor --- Guidance and integration:** explain concepts, review

    reproducibility, and coordinate the final end-to-end demonstration.

Students should rotate notebook walkthroughs and review one another's
work so that all three understand the complete pipeline. The
responsibilities are starting points; everyone should participate in
training, evaluation, and deployment.

## Troubleshooting

**Wrong Jupyter kernel:** activate `cubesat-ml`, launch Jupyter, and
select **Python (cubesat-ml)**.

**GPU not detected:**

``` bash
python -c "import tensorflow as tf; print(tf.config.list_physical_devices('GPU'))"
```

Continue on CPU if necessary; check NVIDIA driver/WSL configuration for
GPU support.

**Dependency conflicts:**

``` bash
python -m pip check
```

Share the complete output before changing versions.

**Dataset download fails:** check internet, rerun the loading cell, and
inspect the full error.

**Notebook appears stuck:** check whether data/weights are downloading
and inspect CPU/GPU use. Interrupt/restart only if needed, then rerun
from the top.

**Slow Pi inference:** verify the optimized model is being used and
report measured timing; do not claim real-time performance without
measurement.

## Important notes

-   Keep the test set separate from training and model selection.
-   Use the same test split for model comparisons.
-   Record random seeds and training settings where provided.
-   Report the dataset and split alongside metrics.
-   This is an educational prototype, not a flight-qualified or
    safety-critical CubeSat system.
